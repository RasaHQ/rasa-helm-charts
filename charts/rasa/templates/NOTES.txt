2. Upgrading from 2.x? Three changes need action OUTSIDE your values file:

   a) The Deployment selector changed, and Kubernetes will not let you edit it.
      `helm upgrade` FAILS on an existing release. Delete first, accept downtime:
        kubectl delete deployment <release>-rasa -n <namespace>
        helm upgrade <release> ...
      Do NOT use --cascade=orphan: the orphaned pods can never be adopted and
      survive `helm uninstall`.

   b) The licence Secret key default is now RASA_LICENSE, not rasaProLicense.
      A chart cannot rename a key inside your Secret, so the pod will not start
      until you rename it there, or pin the old name:
        rasa: {license: {secretName: rasa-secrets, secretKey: rasaProLicense}}

   c) Deployment settings moved from rasa.* to the chart ROOT. rasa.image,
      rasa.resources, rasa.nodeSelector, rasa.service, rasa.ingress and the
      rest are now top-level; rasa.* keeps only Rasa's own config (port,
      enableApi, cors, endpoints, integrations, license, ...).
      Old keys are IGNORED, not rejected, so a stale rasa.image silently falls
      back to the chart default image. Also ignored: rasa.settings.*,
      additional* (now extra*), volumes, volumeMounts, rasa.credentials,
      useDefaultArgs, rasa.enabled, rasa.scheme, and the actionServer /
      duckling / rasaProServices components.

   Full migration guide, including every removed and renamed key:
   https://github.com/RasaHQ/rasa-helm-charts/blob/main/charts/rasa/MIGRATION.md
{{- end }}

{{- if include "rasa.apiUnauthenticated" . }}

   WARNING: the Rasa HTTP API is enabled and NOT authenticated.
   No credential reaches the container, so anything that can reach the Service
   can call the API, including the model-management endpoints. The chart warns
   here and REFUSES to render if you route traffic to it - ingress.enabled, a
   service.type other than ClusterIP, or hostNetwork. A ClusterIP Service is
   not a boundary either, and a route added outside this chart is invisible.
   Fix it:
     --set rasa.authToken.secretName=rasa-secrets \
     --set rasa.authToken.secretKey=AUTH_TOKEN    # the Secret must hold this key
   Or --set rasa.enableApi=false (needs a model; rasa run exits without either).
   Or --set rasa.allowUnauthenticatedApi=true to accept an open API.
{{- end }}
