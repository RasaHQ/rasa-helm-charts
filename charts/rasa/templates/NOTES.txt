{{- else if contains "ClusterIP" .Values.rasa.service.type }}
  export POD_NAME=$(kubectl get pods --namespace {{ .Release.Namespace }} -l "app.kubernetes.io/name={{ include "rasa.name" . }},app.kubernetes.io/instance={{ .Release.Name }}" -o jsonpath="{.items[0].metadata.name}")

  echo "Visit http://127.0.0.1:8080 to use your application"
  kubectl --namespace {{ .Release.Namespace }} port-forward $POD_NAME 8080:$CONTAINER_PORT
{{- end }}

2. Breaking changes in chart 3.0.0:
   - The actionServer, duckling and rasaProServices components have been removed.
     This chart now deploys the Rasa Pro server only. Their values keys are ignored
     rather than rejected, so an existing values file still installs.
   - Action servers are bring-your-own. Deploy one yourself and point
     rasa.endpoints.action_endpoint.url at it. If you were using the
     chart-managed action server, do this BEFORE upgrading: the pod starts either
     way and the failure only appears on the first custom-action call.
   - RASA_DUCKLING_HTTP_URL is no longer set, and rasa.ducklingHttpUrl is
     gone. Set the variable yourself via rasa.extraEnv if you run Duckling.
   - rasa.containerSecurityContext now defaults to the restricted Pod Security Standard:
     allowPrivilegeEscalation: false, capabilities.drop: [ALL], runAsNonRoot: true and
     seccompProfile.type: RuntimeDefault. No runAsUser is set, so the effective uid is
     still whatever the image declares.
   - rasa.automountServiceAccountToken now defaults to false, so no Kubernetes API token
     is mounted. Rasa Pro does not call the Kubernetes API and this chart grants no RBAC.
     Set it to true if you add a sidecar via rasa.extraContainers that needs one.
   - Chart.yaml declares appVersion again, tracking the Rasa Pro release the chart
     targets. rasa.image.tag now defaults to "" and falls back to appVersion, so a chart
     upgrade moves the Rasa Pro image with it. Set rasa.image.tag to an exact tag to pin
     the image independently.
   - rasa.authToken and rasa.jwtSecret are now unset by default, so a
     default install no longer needs authToken and jwtSecret keys in its Secret. If you
     relied on the old defaults without setting them explicitly, this upgrade REMOVES
     AUTH_TOKEN and JWT_SECRET from the pod and leaves the HTTP API unauthenticated.
   - app.kubernetes.io/name is now the chart name ("rasa") instead of the release
     fullname. This label is part of Deployment.spec.selector, which Kubernetes does
     not allow you to change, so `helm upgrade` FAILS on an existing release. Delete
     the old Deployment first and accept the downtime:
       kubectl delete deployment <release>-rasa -n <namespace>
       helm upgrade <release> ...
     Do NOT use --cascade=orphan here. The orphaned ReplicaSet keeps the old labels,
     which the new selector cannot match, so nothing ever adopts it: the old pods
     outlive the release, survive `helm uninstall` and are never garbage collected.
     They also leave the Service the moment its selector flips, so orphaning buys no
     continuity. To avoid downtime, install alongside under a second release name and
     cut traffic over yourself.
   - NetworkPolicy objects are now named after the release and select only this
     release's pods. Previously deny-all and allow-dns-access selected EVERY pod in
     the namespace, and allow-dns-access was a fixed name that collided between
     releases. If you relied on this chart imposing a namespace-wide default-deny,
     that is now scoped to the chart's own pods.
   - networkPolicy gained dnsNamespace, egressPorts and allowIngressFrom. Egress is
     still limited to 443 and 80 by default, so add your tracker store and event
     broker ports before enabling denyAll, and list your ingress controller in
     allowIngressFrom or its traffic is dropped.
   - rasa.ingress.hosts is now empty by default instead of carrying a placeholder
     host with a /api path. Enabling the ingress without hosts is refused.
   - enableApi now defaults to FALSE. The Rasa HTTP API (model management,
     conversation and tracker endpoints) is opt-in. Set rasa.enableApi=true if your
     integration needs it, and set authToken or jwtSecret when you do.
   - The pass-through keys follow the usual Helm naming now:
       additionalArgs -> extraArgs        additionalEnv -> extraEnv
       additionalContainers -> extraContainers
       volumes -> extraVolumes            volumeMounts -> extraVolumeMounts
       overrideEnv -> env                 global.additionalDeploymentLabels ->
                                          global.extraDeploymentLabels
     The old names are IGNORED, not rejected, so anything left under them is
     silently dropped. Move them before upgrading.
   - useDefaultArgs is gone. args now has three states: unset means the chart
     builds the arguments and appends extraArgs, an explicit list replaces them,
     and an explicit empty list ([]) means no arguments at all — that last one is
     what useDefaultArgs=false used to do.
   - enableApi=true now REQUIRES a credential. The chart refuses to render an
     enabled API with no authToken, jwtSecret or AUTH_TOKEN/JWT_SECRET reaching
     the container. A ClusterIP Service is not a boundary, so this no longer waits
     for an ingress. Set allowUnauthenticatedApi=true to accept the risk.
   - Rasa settings live directly under rasa.*. Anything left under rasa.settings is
     IGNORED, not rejected, so a port, authToken, endpoints or tracker_store left
     there silently reverts to the chart default. Move them before upgrading.
   - rasa.enabled was removed. The chart deploys one workload, so there is nothing
     to toggle: install to deploy, uninstall to remove. If you used rasa.enabled=false
     to install this chart for its NetworkPolicies alone, it now deploys the server too.
   - rasa.scheme is gone. Nothing read it.
   - rasa.cors is a plain string again. It was typed as "string or secret
     reference"; the secret form was never read and rendered map[...] into --cors.
   - The container port, the Service targetPort and the NetworkPolicy ports all follow
     rasa.port now instead of rasa.service.port, so they cannot drift from the
     port Rasa actually binds. service.targetPort defaults to empty and follows
     port; set it only to target a different or named container port.
   - The helm test hook Pod now runs non-root (uid 65534) with the restricted fields set,
     so `helm test` works in a namespace enforcing the restricted Pod Security Standard.
{{- if and (include "rasa.apiServed" .) (not (include "rasa.apiAuthenticated" .)) }}

   WARNING: the Rasa HTTP API is enabled and NOT authenticated.
   enableApi is true but neither authToken nor jwtSecret is set,
   so anything that can reach the Service inside the cluster can call the API. Set one of
   them before exposing this deployment more widely:
     --set rasa.authToken.secretName=rasa-secrets \
     --set rasa.authToken.secretKey=authToken
   Or disable the API with --set rasa.enableApi=false
   Exposing it outside the cluster in this state is refused outright - that means an
   ingress, a non-ClusterIP service type, or hostNetwork. Override with
   --set rasa.allowUnauthenticatedApi=true only if something in front of the
   chart already authenticates callers.
{{- end }}

{{- if and .Values.rasa.containerSecurityContext.enabled .Values.rasa.containerSecurityContext.runAsNonRoot (ne .Values.rasa.image.repository $defaultRepo) }}

   WARNING: you are running a custom Rasa Pro image:
     {{ .Values.rasa.image.repository }}
   runAsNonRoot: true requires an image whose USER is a NUMERIC non-root uid. The stock
   image is USER 1001. If yours runs as root, or declares USER by name, the pod fails with
   CreateContainerConfigError and never starts. Check your image with:
     docker image inspect --format '{{ "{{.Config.User}}" }}' {{ .Values.rasa.image.repository }}:{{ .Values.rasa.image.tag | default .Chart.AppVersion }}
   To opt out (the pod will then not satisfy the restricted Pod Security Standard):
     --set rasa.containerSecurityContext.runAsNonRoot=false
{{- end }}
