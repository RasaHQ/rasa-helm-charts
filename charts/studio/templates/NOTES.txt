2. Upgrading from 2.x? Four things need action outside your values file:

   a) Delete the orphaned resources from the old topology:
        kubectl delete deployment,svc,ingress,sa,hpa -l app.kubernetes.io/component=studio-backend -n {{ .Release.Namespace }}
        kubectl delete deployment,svc,ingress,sa -l app.kubernetes.io/component=studio-web-client -n {{ .Release.Namespace }}
        kubectl delete deployment,sa,hpa -l app.kubernetes.io/component=studio-event-ingestion -n {{ .Release.Namespace }}
      Also remove old jobs/sa named *-database-migration or *-db-migration.
{{- if .Values.rasa.enabled }}

   b) Delete the Rasa Deployment. The rasa subchart changed a selector label,
      which Kubernetes treats as immutable, so `helm upgrade` fails without it:
        kubectl delete deployment {{ .Values.rasa.fullnameOverride | default "rasapro" }} -n {{ .Release.Namespace }}
{{- end }}

   c) Keycloak is gone. Better Auth serves login at /api/auth/*. Confirm your
      users exist in Better Auth BEFORE dropping the Keycloak database, then
      drop the unused KEYCLOAK_* keys from studio-secrets. If any Keycloak
      objects survive:
        kubectl delete deployment,svc,ingress,sa,networkpolicy -l app.kubernetes.io/component=studio-keycloak -n {{ .Release.Namespace }}

   d) Old values keys are IGNORED, not rejected, so anything left under them is
      silently dropped: backend (now app), webClient (now app.webClient),
      keycloak, config.keycloak, config.database.keycloakDatabaseName,
      rasa.rasa.<deployment key> (now rasa.<key>), and additional* (now
      extra*): additionalDeploymentLabels, additionalContainers,
      additionalAnnotations.

   Full migration guide:
   https://github.com/RasaHQ/rasa-helm-charts/blob/main/charts/studio/README.md#upgrading-to-chart-300
{{- end }}
